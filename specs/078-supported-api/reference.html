Issue 78: Hosted API reference

Extend /api/docs in the Strata image. Baseline: Canary returned OpenAPI 1.0.0 with 106 operations. Express mounts the v1 domain routers, dedicated reads, OAuth, connection management, and browser session aliases in server/src/app.ts. API policies and shared input schemas live in server/src/api; browser authorization still runs in the same domain handlers.

Design and acceptance

  1. Serve a public guide and static reference assets with the same image. Load only the same origin versioned OpenAPI URL without credentials, cache, or redirects. Show its API version and SHA-256 identity. Preserve existing guide anchors and leave runtime authorization intact.
  2. Build the operation index from every published method/path, with topical groups and an explicit fallback. Search purpose, method, path, tag and documented access; filter method and area. Use reversible fragments and browser history. Show only the selected operation in detail.
  3. Show authentication separately from authorization, and label unknown policy. Render parameters, media variants, statuses, headers and nested schema fields. Keep contract text inert and recursive references bounded. Use contract examples validated at source, or state why none is verified; provide placeholder request templates and no execution UI.
  4. Keep practical guides for personal and service credentials, OAuth, paging, errors and approved writes. Link walkthroughs to actual operations. Distinguish application rate windows from any edge policy.
  5. Verify actual Express route registration in both directions, document exclusions with reasons, and compare index keys to the contract. Verify search, fallback, links, keyboard/mobile, malformed/unavailable contracts, and malicious content. Verify the exact Canary candidate before PM review.

Maintenance boundaries

Published inventory and supplemental permission metadata belong in server/src/api/documentation.ts. The renderer uses local JSON pointers and handles the constructs in the Strata contract; unknown or external constructs remain visible without fetching external references. Guidance must describe verified policy only. Keep tenant data and secrets out of examples and evidence.
