Supported API and agent authentication

Approved scope: Issue 78. Source baseline: b06159b6073e8ded3a7d9ca69c031b2bb974b17b. This specification records intended behavior; tests and release evidence establish verification.

Source findings

  • server/src/app.ts mounts all Web UI domain operations under /api and attaches cookie authentication.
  • server/src/auth/session.ts reloads the user and membership grants on each request. server/src/rbac/policies.ts and permissions.ts provide shared policy.
  • server/src/content/commit-operation.ts and invitation-routes.ts revalidate cookie sessions; they must also revalidate API principals.
  • buildSessionPayload currently includes the user's entire authorized application state. Credential resource limits must apply before this state reaches an API caller.
  • Issue 67 remains Backlog. This issue owns reusable credentials, operation contracts and the REST boundary. No MCP, extension or connector implementation is activated.

Contract and boundaries

AreaRequired behavior
Supported operations/api/v1 reuses the Web UI routers and domain/RBAC services. Explicit versioned operation inventory covers every server-backed UI operation. Read endpoints expose scoped resources with bounded pagination. Client-only search/filter/view rendering operates on these documented resources.
CredentialsNamed PATs, maximum 90-day expiry; OAuth grants maximum 30 days; opaque 256-bit secrets stored only as SHA-256 digests. Access tokens expire after 10 minutes. Every request and renewal checks revocation, expiry, active account, current authority, approved authority ceiling, scopes and resource boundaries. No bearer credential can create another credential or gain a browser session.
Scopes and resourcesContent read/write/manage, administration read/write, account read/write/security. Approved resources: account (account scopes only), platform, workspace IDs or board IDs. Platform requires current System Admin. Scoped issuers cannot grant unavailable permissions. Approval captures an authority ceiling, preventing later role promotion from expanding existing credentials.
Device flowPublic named clients request a 10-minute device code and human-readable matching code. Browser-only consent displays client, permissions, resources and expiry, with explicit confirmation, denial and cancellation. Five-second polling interval increases by five seconds on early polling. Redemption is atomic and single-use.
PKCEAuthenticated users register public clients and exact HTTPS or loopback-IP redirect URIs. Authorization requires state and S256 PKCE. Browser consent precedes a single-use 60-second code bound to client, redirect URI and challenge. No embedded shared secret or implicit/password grant.
RefreshRotate refresh tokens atomically, keep consumed hashes until grant expiry, revoke the token family on replay, never extend approved scope/resources/expiry. Concurrent renewal has one winner and replay invalidates its family.
Browser and auditExisting browser authentication remains supported. Connection management is browser-session-only with deliberate JSON requests and same-origin checks. Domain audits include credential and operation identity; lifecycle audits contain safe IDs and approved grant metadata, never raw credentials.
Transport and limitsCredentials require TLS outside explicitly local development. No credentials in query strings. No-store sensitive responses. Persistent bounded rate counters for issuance, consent lookup and API/token use; documented 429/Retry-After behavior. Error payloads do not disclose hidden resource contents.

Security dependency review

Production dependency audit initially reported 31 advisories. Targeted patches update Zod to 4.6.6, the coupled Tiptap packages to 3.30.5, body-parser to 2.4.0, proxy-addr to 2.0.8 and qs to 6.17.1. Optional Tiptap menus are pinned to the same release to preserve peer compatibility. No force or legacy peer resolution is used. After installation, npm audit --omit=dev reports zero advisories. The full development toolchain audit still reports 23 existing advisories; those tools are removed from the runtime image. This is not a claim that all repository dependencies are vulnerability-free.

Reviewed vendor advisories through the internal browser on November 10, 2026: Zod memory exhaustion, body-parser compressed request handling, proxy-addr trust parsing, Tiptap DOM XSS, Tiptap Markdown parsing, and qs stringify denial of service. Advisory presence alone does not establish exploitability in Strata; these patches remove the reported vulnerable runtime versions.
